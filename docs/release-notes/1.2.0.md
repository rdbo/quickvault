# QuickVault 1.2.0

The app gets a new engine room: the Dioxus renderer is replaced by Tauri 2
with a Leptos page in WebAssembly, on Linux, Windows and Android. Screens,
features and shortcuts are unchanged. Formats are unchanged: 1.2.0 opens and
writes the same vault, archive and snapshot formats as 1.0.0–1.1.1
(spec 0015).

This file is the release record that 0012 §3 asks for. Everything in the
[1.0.0 record](1.0.0.md) about signing, build inputs, the security status
and known limitations still applies; this file lists only what changed and
what was checked for it.

## What changed (plans 0070, 0071)

- **No local server any more.** Dioxus sent every screen update over a
  websocket on a loopback port, and attachment previews over a second
  loopback listener. The app now runs fully in process: nothing listens on a
  socket. The connection whose drops 1.1.1 had to work around (a screen
  that stopped reacting after a quick app switch) no longer exists.
- **How screens reach the page.** Rust builds each screen as a frame; the
  page renders it and sends typed actions back through one bounded command
  (64 KiB, strict decoding). The page never sees vault handles: it gets
  random references that a lock clears. Previews stream over an in-process
  scheme, at most 64 KiB per response, revoked on close, lock and hide.
- **Webview hardening carried over.** Strict CSP (no inline script), exact
  navigation checks, no new windows, downloads or developer tools, and an
  incognito webview. On Linux the context menu still appears only in text
  fields (Paste, Delete, Select All), and permission, file-chooser and
  sign-in prompts are refused. On Windows, browser shortcuts (reload, find,
  print) do nothing in the app.
- **Android** keeps its application ID, signing key, version-code rule
  (1.2.0 → 10200) and component names, so it updates over 1.1.1 and keeps
  the autofill-service setting. Back still closes menus and screens first.
- **Nothing vendored.** The patched `dioxus-desktop` copy in `third-party/`
  is gone; every dependency comes from crates.io at an exact version.

Specs 0003 §6.4, 0008 §1.1/§4, 0009 (client table, §1.8, §4, §6) and
0012 §1 were amended for the new renderer; see their changelogs.

## Build inputs

- Toolchain: Rust 1.98.1 (`rust-toolchain.toml`), unchanged; the page also
  needs the `wasm32-unknown-unknown` target.
- Tools: wasm-bindgen-cli 0.2.129 (builds the page) and tauri-cli 2.12.4
  (Android), both pinned in CI.
- Dependencies: Tauri 2.12.5 and Leptos 0.8.23 replace Dioxus 0.7.10. The
  dependency record, with the exact licence exceptions, two
  unmaintained-crate advisories and why they do not apply, and 204 new
  `cargo vet` exemptions (development audit debt), is
  `plans/0071-tauri-leptos-migration/DEPENDENCIES.md`.
- Vendored: nothing (the `dioxus-desktop` fork was removed).

## Review status

Plan 0071 has had no fresh-context review yet. It replaces the webview
bridge, the preview transport and the Android packaging. No independent
security audit has been done.
