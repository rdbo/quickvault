# LAN v2 development vectors

These fixtures check exact bytes, parameters and component interoperability.
They are not independent review of the QuickVault composition and do not
satisfy the D12 release gate.

`qv-dev-lan-v2.txt` is generated by `generate-lan-v2.py`, using Python's
SHA-256/HMAC-SHA-512, cryptography's HKDF and PyNaCl/libsodium's XChaCha20-Poly1305.
It covers all three mode/intent combinations, directional epoch keys,
FinishedB, key proofs, commitments, comparison codes, AAD and ciphertexts.
`qv-dev-lan-v2-wire.txt`, generated by `generate-lan-v2-wire.py`, independently
encodes the canonical message/transcript/QR bytes with cbor2. Its OPAQUE and
slot ciphertext fields are **synthetic shapes**, not a successful PAKE or
usable credential. X-Wing public/ciphertext bytes come from the existing
pinned component fixture.

cffi2.1.1 and pycparser3.12. Temporary validation tools are not product or
repository dependencies. Downloaded wheels were recorded with SHA-256:

at the v4.0.1 tag commit `75fe4cdddb7946440054da0c8e7cdd73828af3f9`.
The source is609786 bytes, SHA-256
`cb9193aff331a1080a3fc69cab2d7b34cc6d196d04fcdafb243c9fab2adb8959`.
The fixture retains the upstream copyright/license attribution. The Rust test
replays serialized client/server states and compares finalization, session and
export bytes. That component vector deliberately uses upstream's **Identity
KSF test suite**. Production uses the separate fixed Argon2id suite; this
fixture must never be used to select production parameters. Production
real-KDF matching/rejection and RNG-failure tests are separate evidence.
